# Engineering workflow release 0.5.1

Reviewed 2026-10-01. No production project changes or controller operations.

## Changes

- One current route: discover/attach, engineer, edit in IDE, Save All/read back,
  fresh Build/Make, approved reopen/recompile, evidence handoff. Historical private
  native-format notes and older capability audits are explicitly superseded.
- Seven read-only edit guides, including engineering. The engineering guide returns
  the actual bundled reference text, so the harness need not guess an installation path.
- General engineering checklist covers tasks/FB lifecycle, coordinates/cams, continuous
  targets, registration chatter/FIFO, PLC authority, signed/scaled IO, stop/park/home,
  diagnostic traces, maximum-speed analysis and behavioral acceptance.
- Source/version boundaries are explicit: official catalog, historical programming
  editions, local MP2600iec/Sigma-5 setup references, and conditional firmware findings.
- Verification is dependency-injected for regression coverage. Approved reopen is
  followed by another fresh Build/Make and program-integrity comparison. Missing
  validation, hashes, clean-save state, close or matching-open evidence fails closed.
- Failed tool steps retain tool/phase/error in the existing atomic JSON report path.
- Cross-workspace wrapper refusal test now supplies valid required arguments.

## Evidence

`npm test` passed all 16 suite stages, including 21 injected acceptance-flow cases,
45 render contracts, seven guides, retirement, skill delivery, workspace/consent guards,
Python native-format/knowledge tests, host-to-Python integration and bridge guards.
The first sandbox run hit Python temporary-directory access restrictions; the complete
suite passed with the authorized subprocess execution outside that sandbox.

`npm pack --dry-run` checked the release contents. The verifier, guidance and new tests
are packaged. No vendor PDFs, customer projects, controller downloads or live smoke
results are generated by these regressions.
